# PRODUCT_SENSE.md — 제품 원칙

1. **탐지 이후가 제품의 핵심**  
   보고서 생성보다 원인·수정·검증·전달의 연결을 우선합니다.

2. **안전한 자동화가 완전 자동화보다 우선**  
   근거가 부족하면 사람 검토로 멈추는 것이 잘못된 자동 패치보다 낫습니다.

3. **최소 diff**  
   개발자가 리뷰할 수 있고 rollback하기 쉬운 패치를 선호합니다.

4. **검증 가능성**  
   기능은 CLI/API 출력뿐 아니라 테스트와 evidence로 확인할 수 있어야 합니다.

5. **도구 교체 가능성**  
   특정 scanner/LLM/vendor에 파이프라인 의미를 묶지 않고 공통 schema와 provider 경계를 둡니다.

6. **실패 데이터의 가치**  
   실패한 후보는 패치 정책·프롬프트·규칙 개선을 위한 연구 데이터입니다.

7. **초기 PR 중심**  
   초기 제품은 production 자동 배포보다 verified branch/PR 전달을 완료 기준으로 둡니다.
