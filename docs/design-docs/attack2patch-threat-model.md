# Attack2Patch 위협 모델

## 보호 자산

- 소스 코드와 패치 작업 복사본
- Docker 호스트 제어 권한
- 배포 승인 상태
- 공격 로그와 민감정보
- 이전 정상 이미지

## 신뢰 경계

- HTTP 요청 및 로그는 비신뢰 입력이다.
- 생성된 패치도 검증 전까지 비신뢰 입력이다.
- Docker 명령은 전용 Runtime 모듈만 수행한다.

## 주요 위협과 완화

| 위협 | 완화책 |
| --- | --- |
| 로그를 통한 명령 주입 | 셸 문자열 결합 금지, 허용된 인자만 전달 |
| 경로 조작 | 저장소 상대 경로 정규화 및 허용 루트 검사 |
| 악성 패치 | Diff 검토, 정적 분석, 테스트, 수동 승인 |
| 무단 배포 | 승인 상태 서버 측 검증 |
| Docker 권한 탈취 | 소켓 외부 노출 금지, 배포 기능 최소화 |
| 민감정보 저장 | 저장 전 토큰·쿠키·비밀번호 마스킹 |
