# 핵심 신념

- 상태: ACCEPTED
- 결정일: 2026-08-11

1. 취약점 보고보다 수정과 검증의 연결이 중요합니다.
2. LLM은 후보 생성자이며 최종 판정자는 실행 evidence입니다.
3. 최소 diff가 리뷰·rollback·원인 격리에 유리합니다.
4. 자동화는 허가와 자율성 게이트 안에서만 동작합니다.
5. 실패는 숨길 오류가 아니라 다음 후보와 연구를 위한 데이터입니다.
6. 복잡한 취약점을 억지로 자동 수정하지 않습니다.
7. scanner/vendor 교체가 가능하도록 공통 schema와 provider 경계를 둡니다.
